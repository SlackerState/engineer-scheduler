# 工单工作台

服务工单的一站式桌面工作台（Windows / Mac 通用），最早由「工程师排班表.xlsm」做成，现在接上了 Udesk 和 D365：
在 Udesk 建服务订单，自动拉取 D365 工单（状态、工程师、出发/到达/完工时间、处理进度），派工改约，按整天排班，
加配件、申请借料、提交审批、配件核销、借料归还，以及工程师工作量统计。

> 程序文件名仍是「工程师排班管理」（`工程师排班管理.exe` / `工程师排班管理.app`），旧版本的在线更新按这个名字找新程序，所以先不改；数据目录也仍是 `EngineerScheduler`。

## 数据从哪来

在 Udesk 里创建的服务订单（SVC-xxxxx）会被三一中间件推送到 D365 的「服务订单」实体 `mcs_serviceorder`，并带有：

| D365 字段 | 含义 |
|---|---|
| `mcs_ordersource = 60` | 订单来源 = Udesk |
| `mcs_referencenumber` | 外部系统工单号，即 Udesk 的 SVC-xxxxx |
| `mcs_ordernumber` | 服务订单号（如 2610028417） |
| `mcs_orderstatus` | 订单状态（已创建 / 已派工 / 已接收 / 已出发 / 已到达 / 现场完工 / 服务完工 …） |
| `_mcs_engineer_value` | 工程师 |
| `mcs_appointmenttime` 等 | 预约上门、派单、出发、到达、现场完工时间 |
| `_mcs_networkid_value` | 服务网点（默认只同步 `UK Kent 01 S`） |

所以软件只需要登录 D365 一个系统：按「来源 = Udesk + 最近 N 天」拉单，就能拿到 Udesk 创建的所有订单及其 D365 详情。Udesk 里建了单、但还没推送到 D365 的（CRM 工单号为空），要等推送成功后才会出现。

## 功能（对应原 Excel 各页）

- **订单清单**：自动同步 + 手工新增，可按状态、工程师、关键字筛选；点一行可编辑借料单号、处理进度等本地记录，并查看 D365 信息、直接在 D365 打开。「新建服务订单（Udesk）」在软件里直接建 Udesk 服务订单（见下）。
- **查工单**：输入机台号，直接看这台机下面所有服务单（按机台分组，显示未完成几单）；也可以输入任意服务单号或 SVC 号，部分号码也行（没有完全相同的号码时按包含查，最多 200 单）。直接查 D365，不限来源（手动单、Udesk 单都有）、不限时间、不限网点。点一行打开和订单清单一样的详情，处理进度、配件、派工、申请借料、核销都能用。只是打开看的工单不进订单清单、排班、工作量和配件统计；在这单上做了 D365 操作、定了计划上门，或点「加入订单清单」后才进。
- **新建服务订单（Udesk）**：和 Udesk 里「建单 → 服务订单」插件一样，提交到三一中间件（sanyi-mid），生成 SVC 单并推送到 D365。输入设备编号查出客户、机型、国家，自动预填联系人、电话、服务目的地；必填订单类型（召请 / 保养 / 开机）、来源渠道（本地热线 / 即时消息 / 工程师转接）、联系人、电话（≤20）、服务目的地（≤50）；召请必须写订单描述，开机必须选服务工程师，预约时间可不填（填了要在 30 天内）。建单后从「我创建的」拿到 SVC 号和 D365 订单号，并马上从 D365 拉进订单清单。需要先在设置里填自己的 Udesk 坐席 ID（Udesk 建单页地址里的 agentId）。注意：这个中间件接口本身不校验登录，只凭坐席 ID 记录是谁建的。
- **在软件里改 D365 工单**（写回 D365，规则与 D365 表单一致）：
  - **派工 / 改派工程师**：已创建 → 派工（`Service_DispatchEngineerApi`），已派工 / 已接收 → 转派（`Service_TransferEngineerApi`），审批中的单不能转派；工程师名单来自 D365 派工对话框（`Service_GetEngineerListApi`）。可勾选多单「批量改派」。
  - **改预约上门时间**：只在「已创建」状态可改（D365 规定之后只有 CC 角色能改），会同时累加「预约时间修改次数」。
  - 写入前会重新读取 D365 的实时状态再判断；写入后立刻读回，订单清单、派单记录和排班表一起更新。
  - 订单状态（接收 / 出发 / 到达 / 完工…）由工程师 App 和 D365 后台流程推进，软件不直接改，只同步显示。
- **排班表**：按整天，每人每天一格，点格子看当天工单、选状态（空闲、外出、驻点、休假、培训、休息）；橙色 = 已派单（右上角是当天单数），红色 = 已派单但当天休假/培训/休息/驻点（冲突）；底部「外勤可派人数 / 驻点在岗人数」为 0 标红、为 1 标橙。
- **今日查询**：任意日期，看谁有空、当天派了几单。
- **维修三快**：同 GSC 指挥中心（bop-gsc.sanyglobal.com）「调度中心 → 维修调度」，只算直销和合资公司的单（英国国区，不含服务经销商）。上面四张卡片是待接收 / 待出发 / 待到达 / 待完工各有几单、触发预警几单、已超时几单（待完工另有暂停维修），点卡片只看这个节点；下面每单一行：当前节点、剩余或超时时间（超时红色、预警橙色）、订单状态、工程师、客户、设备、召请类型、借料 / 领料单号，超时的排最前，可按「已超时 / 预警 / 正常」筛选。点单号打开工单详情（不在订单清单里的单同「查工单」只查看）。GSC 由本人在弹出的浏览器窗口里登录（三一统一登录），没登录或过期时页面上有「登录 GSC」。
- **工作量**：回看任意时间段（本周 / 上周 / 本月 / 上月 / 近 30 天 / 今年 / 自定义）每位工程师的上门工单、上门天数、完工、现场工时（到达 → 现场完工，单次超过 12 小时的视为完工没及时提交，不计入、单独计数）、平均响应（派工 → 到达）、超期、配件消耗和收费金额，以及排班（只算工作日、按整天算）各状态的天数，周末上门单独计数；点一行看这位工程师的排班日历和工单明细；可导出 Excel（汇总、工单明细、排班明细）。历史排班和工单都存在本地，排班表也可以往前翻到任意一周。
- **上门时间与排班**：D365 的「预约上门时间」是考核用的截止时间，创单时通常往后写（实测 84% 的单比预约日提前上门，中位数提前约 5 天），所以**不用它排班**。排班表按 **实际到达 → 出发 → 计划上门**（调度员在软件里定的日期，只存本地）放置；三者都没有的单进「待排期」列表（排班表下方），按预约截止时间排序，选日期即可排进去。时间变了派单会自动挪动，自动标的「外出」也会跟着撤销（手工标的不动）。
- **超期提醒**：以预约上门时间为考核截止 —— 已超期未到达、即将超期（默认 24 小时内，可在设置里改）、计划上门晚于截止，都会在订单清单、今日查询、排班表里标出；订单清单可筛选「超期风险」「待排期」。
- **配件**（随「同步 D365」更新，来自 D365 的服务配件和领料/借料/归还单）：
  - **借料归还**：每张借料单的配件借出/剩余数量和归还状态 —— 待归还（工单已完工、还有剩余、没申请归还）、归还被拒、审批通过待退、归还审批中、借用中、借料待提交、借料审批中、已用完、已归还；审批通过的借料单旁显示 D365 的发货状态（Shipped 已发货 / Partially Shipped 部分发货 / Not Shipped 未发货），工单详情里同样显示；默认只看需要处理的，点单据号直接在 D365 打开处理。
  - **收费配件**：按工单日期、工程师筛选配件消耗明细，显示是否收费、单价、折扣、金额和收费合计。
  - 工单详情里也能看到这一单的配件、收费合计和借料归还情况，以及 D365 的「服务订单处理进度」（工程师填写的每条进展：时间、填写人、内容），可单独「从 D365 刷新」。打开详情时会自动从 D365 重新读一次这一单，工程师、状态、上门时间等在 D365 里改过（如 CC 改派）会马上显示，不用等下次同步；D365 撤销派工后本地的工程师和排班也会清掉。
  - **改消耗**（写回 D365）：工单详情的配件表里直接改「消耗」数量并保存，写入 D365 的服务配件「消耗数量」，D365 会按 剩余 = 确认 − 消耗 重算剩余数量和金额，借料归还状态随之更新。规则同 D365 表单：0 ≤ 消耗 ≤ 确认数量；已核销、已在归还单上的配件，以及已取消 / 提交审批 / 服务完工 / 远程完工 / 异常完工的工单不能改（显示 🔒 和原因）。写入前会重新读取 D365 的实时数据并让你确认。今日查询顶部有「待归还借料」提醒，订单清单可筛选「待归还配件」。
  - **加配件、申请借料**（写入 D365，规则同 D365 工单上的「申请备件」和借料单上的「提交审批」）：工单详情的配件区点「＋ 添加配件」，按物料号或名称查 D365 物料主数据，点「加入」放进待添加清单（可换关键字多次搜索，清单里改数量、看英格兰配件库库存、移除），最后一次性新增为服务配件（行号、确认数量、价格由 D365 生成；个别没加上的留在清单里并显示原因，可以重试），还没申请的配件可以删除；点「申请借料」先检查（工单要在已接收到现场完工之前、「是否存在故障」为是（为否时弹窗里可以直接改为存在故障并写回 D365，可顺带填故障级别 / 优先级 / 确认时间）、不是服务代理商模式；本人在本大区有超期未核销借料时给出提醒（D365 实际不拦，所以只提醒）），核对并可修改收货人 / 电话 / 地址，勾选这次要申请的配件（默认全选），再调用 D365「申请备件」生成「向子公司借料」单（D365 的申请备件会把全部待申请配件放进新单，所以只勾了一部分时，软件随后把没勾的从这张单上移出，它们仍是待申请；没能移出的会弹窗列出）；还没提交审批（已创建 / 已拒绝）的借料单上的配件，在配件表里可以点「移出」回到待申请；借料单在 D365 里被取消后，上面的配件仍挂在已取消的单上（D365 不会放开，申请备件也不会再带上），配件表里标「借料单已取消」，点「重新申请」把它放回待申请并打开申请借料（只勾这一个）；随后打开「借料单信息」（同 D365 借料单「常规」页）：必填订单类型、订单原因、仓库（只能选发货工厂下的配件仓；同一工单已有其它借料单时 D365 锁定仓库与它们一致）、出库方式，D365「申请备件」生成的借料单这几项可能是空的，软件按英国通常的填法预选（向子公司借料 / 紧急备件 / England Parts WH / 子公司出库）并提示，保存后写入 D365，有空着的不让提交审批；另可填接受部分装运、申请原因，卖方 / 工厂 / 客户 / 成本中心 / 供应方式只读，保存后「提交审批」：显示 D365 的配件替换提醒，确认后提交。审批通过、同步 ERP 后，工单详情和配件页的借料单旁会显示 ERP 文档编号（同步失败时显示 ERP 消息）。
  - **配件库存和图片（iWMS + SIS）**：「添加配件」的搜索结果、选中的配件，以及工单详情配件表的物料号旁都有「库存/图片」。上面是 iWMS（三一物流平台 oswms-deu.sanygroup.com）里这个配件在英国各仓的库存：英格兰配件库（2O01_8005）排第一，按库位合并显示数量；「可用」只算存储库位、没锁定的，收货区 / 发货区（已拣货）和锁定的单独标出。中间是 SIS 里这个配件的替代件（同 SIS「配件查询」的「替代件」）：替代成哪个物料号、数量、1对1 还是其它替换、单向（只能用替代件代替这个配件）还是双向、是否强制替代、适用的主机或产品组，每个替代件下面直接显示它在英格兰配件库的可用数量和库位，点物料号看它的完整库存、替代件和图片。下面是 SIS（sis-global.sanygroup.com）里的配件图片，点小图切换；点大图全屏看原图，可滚轮放大、拖动、旋转，左右键切换，Esc 关闭。在「添加配件」里选中配件时会直接显示英格兰配件库的可用数量和库位。两个系统都由本人在弹出的浏览器窗口里登录（iWMS 约 24 小时、SIS 12 小时有效），没登录或过期时弹窗里有「登录 iWMS」/「登录 SIS」；iWMS 登录后软件会自动切到「海外iWMS查询」角色（账号要有这个角色）。
  - **查库存/图片**：「配件」页的「查库存/图片」标签，不用打开工单也能查。输入物料号或英文名称，先在 D365 物料主数据里找，点结果看它在英国各仓的库存、库位和 SIS 图片；输入完整物料号时直接显示。D365 没登录或没找到时，直接按物料号查 iWMS 和 SIS。输入多个物料号（空格、逗号或换行隔开，一次最多 50 个）时批量查：每个配件一行，显示名称、英格兰配件库可用数量和库位、其它仓可用数量、替代件和图片，查到一个填一行，点一行看详细；「复制结果」可粘贴到邮件或 Excel。
  - **借料邮件**：借料单拿到 ERP 号后，工单详情的「借料归还」和配件页「借料归还」右上角有「借料邮件」，自动生成发给仓库的邮件（每位工程师一封：`Hi Team, Please can you give these to 工程师` + 每行「借料单号, ERP 号 (机器 SN)」），点「复制」粘贴到邮件里即可，框里可以先改。配件页列出最近 14 天拿到 ERP 号的借料单，默认勾选今天审批通过的；同步时有借料单新拿到 ERP 号，同步结果里会提示。
  - **配件核销**（写入 D365，同 D365 工单上的「配件核销」）：工单「服务完工」后（服务代理商模式除外）配件区出现「配件核销」，列出 D365 判定可核销的配件（Service_GetServicePartListApi），勾选后「免费核销」或「报单核销」，D365 生成核销单并同步 ERP；工单详情列出核销单、类型、关联借料单和 ERP 订单号，核销后的配件不能再改消耗。已完工、已取消的工单不能加配件。
- **人员**：姓名、类型（外勤/驻点）、电话、备注、**D365 别名**（D365 里叫 `Lee Ryan`、`Winzar Charles` 的人，按姓名中任一单词自动对应；对不上时在这里填别名）。删除有排班或派单历史的人会改为「停用」：不再出现在排班表和今日查询里，但历史排班、工作量都保留，可在人员页下方恢复。
- **下拉框打字筛选**：选项多（10 个以上）的下拉框，如工程师、借料单仓库、创建记录的列筛选，点开后可以直接打字过滤。
- **Excel**：导入原 xlsm（人员、排班、派单记录、订单清单，可重复导入，已有记录会跳过）；导出为 xlsx。

## 第一次使用

1. 打开软件 → 「设置」→「导入 Excel」，选原来的 `工程师排班表.xlsm`。
2. 点左下角「同步 D365」（或「设置」→「系统登录」→「登录 D365」）。第一次会弹出 Chrome/Edge 窗口，用公司账号登录 D365（含 MFA）；登录成功后窗口自动关闭并开始同步。
   「设置」→「系统登录」里还有 iWMS（配件库存）、SIS（配件替代件和图片）和 GSC（维修三快）：每个系统显示是否已登录（iWMS、SIS、GSC 打开设置时自动检查，D365 点「检查」），点「登录」在弹出的窗口里自己登录，登录后窗口自动关闭。
3. 需要定时同步的话，在设置里勾选「自动同步」（自动同步时不会弹登录窗口，登录过期会在左下角提示）。

登录状态保存在本机的软件数据目录里（只在这台电脑上用）。平时微软账号会自动续期；彻底过期时点「同步 D365」会再弹一次登录窗口。

## 运行与打包

需要 Python 3.10 及以上，以及本机装有 Google Chrome 或 Microsoft Edge（Windows 自带 Edge）。

开发运行：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py          # 桌面窗口
.venv/bin/python main.py --web    # 网页模式 http://127.0.0.1:8765
```

打包（**必须在目标系统上打包**，Mac 打不出 exe）：

- Mac：`./build_mac.sh` → `dist/工程师排班管理.app`
- Windows：双击 `build_windows.bat` → `dist\工程师排班管理\工程师排班管理.exe`（整个文件夹一起复制给同事）

Windows 版的窗口用系统自带的 Edge 以「应用模式」打开（没有地址栏，关掉窗口即退出程序），不依赖 .NET；找不到 Edge 时才退回 pywebview。

### 在线更新

软件启动时会自动检查 GitHub Releases 有没有新版本（可在「设置」里关闭，也可以手动点「检查更新」）。有新版本时左上角出现绿色的「⬆ 新版本」按钮，点开能看到更新内容，「下载并更新」→「立即重启更新」后，软件会关闭、替换成新版本并自动重新打开。数据库和 D365 登录状态在系统的应用数据目录里，更新不受影响。

- 发布新版本：改好代码推送后，打一个更大的版本标签（如 `v1.1.0`）并推送，CI 会把标签号写进程序并发布安装包，客户端就能检测到。
- Windows 版如果放在 `C:\Program Files` 这类需要管理员权限的目录，自动替换会失败；请放在用户自己的目录（如桌面、文档）。
- Mac 版只支持 Apple 芯片；在线更新下载的新版本不会被系统标记为“来自网络”，所以不会再弹出“无法验证开发者”。
- v1.0.0 还没有在线更新功能，需要手动下载一次 v1.1.0 及以后的版本，之后就能在线更新了。

### GitHub 自动打包

仓库里的 `.github/workflows/build.yml` 会在每次推送到 `main` 时，在 GitHub 的 Windows 和 Mac 机器上各打一个包，并用网页模式启动一次做冒烟测试：

- 下载：仓库的 **Actions** 页 → 点最新一次「打包」→ 页面底部 Artifacts 里的 `EngineerScheduler-windows` / `EngineerScheduler-macos-arm64`（保留 30 天）。
- 发版：打一个 `v` 开头的标签并推送，两个包会自动发布到 **Releases**：

```bash
git tag v1.0.0
git push origin v1.0.0
```

Mac 包只支持 Apple 芯片（M 系列），而且没有苹果开发者签名：第一次打开如果提示“无法验证开发者”或“已损坏”，在终端执行 `xattr -dr com.apple.quarantine /Applications/工程师排班管理.app` 后再打开（路径换成实际位置）。Windows 首次运行可能出现 SmartScreen 提示，点「更多信息 → 仍要运行」。

## 数据存放位置

- Windows：`%APPDATA%\EngineerScheduler\`
- Mac：`~/Library/Application Support/EngineerScheduler/`

里面的 `data.db` 是全部数据（SQLite），`browser-profile/` 和 `d365-session.json` 是 D365 登录状态。换电脑时复制 `data.db` 即可，登录需要重新做一次。

## 代码结构

```
main.py               入口（桌面窗口 / --web 网页模式）
backend/db.py         SQLite 表结构、设置
backend/logic.py      排班/派单规则（对应原 Excel 公式和宏）
backend/browser.py    Playwright 驱动 Chrome/Edge，保持 D365 登录、调 Web API
backend/d365.py       mcs_serviceorder 查询与字段映射
backend/sync.py       同步流程（拉单 → 订单清单 → 派单/排班）
backend/parts.py      配件：借料归还状态、收费汇总
backend/workload.py   工作量：按时间段统计每位工程师的上门、工时、超期、配件和排班
backend/excel_io.py   Excel 导入导出
backend/updater.py    在线更新（检查 GitHub Releases、下载、替换并重启）
backend/net.py        对外 HTTP 请求（httpx：连接复用、连不上自动重试，代理和证书跟系统走）
backend/sis.py        SIS 配件图片、替代件
backend/iwms.py       iWMS 配件库存和库位
backend/gsc.py        GSC 指挥中心维修调度（维修三快）
backend/udesk.py      Udesk 建服务订单
backend/version.py    版本号（发版时由 CI 按标签写入）
backend/api.py        界面调用的接口
ui/                   界面（HTML/CSS/JS）
ui/vendor/            随软件打包的开源界面库：Tom Select（选项多的下拉框可打字筛选）、Viewer.js（看大图）
```

在设置里可以调整：D365 网址、订单来源、服务网点、回看天数、是否用 D365 状态覆盖本地状态、是否把工单排进排班表、用哪个浏览器、同步时是否在后台运行浏览器。
