# 工程师排班管理

把原来的「工程师排班表.xlsm」做成了桌面软件（Windows / Mac 通用），并接上 D365：自动拉取 **Udesk 创建的服务订单**，显示每单的状态、工程师和预约/出发/到达/完工时间，再把预约自动排进排班表。

## 数据从哪来

在 Udesk 里创建的服务订单（SVC-xxxxx）会被三一中间件推送到 D365 的「服务订单」实体 `mcs_serviceorder`，并带有：

| D365 字段 | 含义 |
|---|---|
| `mcs_ordersource = 60` | 订单来源 = Udesk |
| `mcs_referencenumber` | 外部系统工单号，即 Udesk 的 SVC-xxxxx |
| `mcs_ordernumber` | 服务订单号（如 2610028417） |
| `mcs_orderstatus` | 订单状态（已创建 / 已派工 / 已接收 / 已出发 / 已到达 / 现场完工 / 服务完工 …） |
| `_mcs_engineer_value` | 工程师 |
| `mcs_appointmenttime` 等 | 预约上门、派单、出发、到达、现场完工时间 |
| `_mcs_networkid_value` | 服务网点（默认只同步 `UK Kent 01 S`） |

所以软件只需要登录 D365 一个系统：按「来源 = Udesk + 最近 N 天」拉单，就能拿到 Udesk 创建的所有订单及其 D365 详情。Udesk 里建了单、但还没推送到 D365 的（CRM 工单号为空），要等推送成功后才会出现。

## 功能（对应原 Excel 各页）

- **订单清单**：自动同步 + 手工新增，可按状态、工程师、关键字筛选；点一行可编辑借料单号、处理进度等本地记录，并查看 D365 信息、直接在 D365 打开。「查 D365 订单」可以按订单号或 SVC 号临时查询；「在 Udesk 新建工单」打开 Udesk，新单推送到 D365 后下次同步自动出现。
- **在软件里改 D365 工单**（写回 D365，规则与 D365 表单一致）：
  - **派工 / 改派工程师**：已创建 → 派工（`Service_DispatchEngineerApi`），已派工 / 已接收 → 转派（`Service_TransferEngineerApi`），审批中的单不能转派；工程师名单来自 D365 派工对话框（`Service_GetEngineerListApi`）。可勾选多单「批量改派」。
  - **改预约上门时间**：只在「已创建」状态可改（D365 规定之后只有 CC 角色能改），会同时累加「预约时间修改次数」。
  - 写入前会重新读取 D365 的实时状态再判断；写入后立刻读回，订单清单、派单记录和排班表一起更新。
  - 订单状态（接收 / 出发 / 到达 / 完工…）由工程师 App 和 D365 后台流程推进，软件不直接改，只同步显示。
- **排班表**：每人每天上午/下午，点格子选状态（空闲、外出、驻点、休假、培训、休息）；橙色 = 已派单，红色 = 已派单但该时段休假/培训/休息/驻点（冲突）；底部「外勤可派人数 / 驻点在岗人数」为 0 标红、为 1 标橙。
- **今日查询**：任意日期 + 时段，看谁有空、派了几单。
- **工作量**：回看任意时间段（本周 / 上周 / 本月 / 上月 / 近 30 天 / 今年 / 自定义）每位工程师的上门工单、上门天数、完工、现场工时（到达 → 现场完工，单次超过 12 小时的视为完工没及时提交，不计入、单独计数）、平均响应（派工 → 到达）、超期、配件消耗和收费金额，以及各排班状态的半天数；点一行看这位工程师的排班日历和工单明细；可导出 Excel（汇总、工单明细、排班明细）。历史排班和工单都存在本地，排班表也可以往前翻到任意一周。
- **上门时间与排班**：D365 的「预约上门时间」是考核用的截止时间，创单时通常往后写（实测 84% 的单比预约日提前上门，中位数提前约 5 天），所以**不用它排班**。排班表按 **实际到达 → 出发 → 计划上门**（调度员在软件里定的日期+上午/下午，只存本地）放置；三者都没有的单进「待排期」列表（排班表下方），按预约截止时间排序，选日期即可排进去。时间变了派单会自动挪动，自动标的「外出」也会跟着撤销（手工标的不动）。
- **超期提醒**：以预约上门时间为考核截止 —— 已超期未到达、即将超期（默认 24 小时内，可在设置里改）、计划上门晚于截止，都会在订单清单、今日查询、排班表里标出；订单清单可筛选「超期风险」「待排期」。
- **配件**（随「同步 D365」更新，来自 D365 的服务配件和领料/借料/归还单）：
  - **借料归还**：每张借料单的配件借出/剩余数量和归还状态 —— 待归还（工单已完工、还有剩余、没申请归还）、归还被拒、审批通过待退、归还审批中、借用中、已用完、已归还；默认只看需要处理的，点单据号直接在 D365 打开处理。
  - **收费配件**：按工单日期、工程师筛选配件消耗明细，显示是否收费、单价、折扣、金额和收费合计。
  - 工单详情里也能看到这一单的配件、收费合计和借料归还情况，可单独「从 D365 刷新」。
  - **改消耗**（写回 D365）：工单详情的配件表里直接改「消耗」数量并保存，写入 D365 的服务配件「消耗数量」，D365 会按 剩余 = 确认 − 消耗 重算剩余数量和金额，借料归还状态随之更新。规则同 D365 表单：0 ≤ 消耗 ≤ 确认数量；已核销、已在归还单上的配件，以及已取消 / 提交审批 / 服务完工 / 远程完工 / 异常完工的工单不能改（显示 🔒 和原因）。写入前会重新读取 D365 的实时数据并让你确认。今日查询顶部有「待归还借料」提醒，订单清单可筛选「待归还配件」。
- **人员**：姓名、类型（外勤/驻点）、电话、备注、**D365 别名**（D365 里叫 `Lee Ryan`、`Winzar Charles` 的人，按姓名中任一单词自动对应；对不上时在这里填别名）。删除有排班或派单历史的人会改为「停用」：不再出现在排班表和今日查询里，但历史排班、工作量都保留，可在人员页下方恢复。
- **Excel**：导入原 xlsm（人员、排班、派单记录、订单清单，可重复导入，已有记录会跳过）；导出为 xlsx。

## 第一次使用

1. 打开软件 → 「设置」→「导入 Excel」，选原来的 `工程师排班表.xlsm`。
2. 点左下角「同步 D365」（或「设置」→「登录 D365」）。第一次会弹出 Chrome/Edge 窗口，用公司账号登录 D365（含 MFA）；登录成功后窗口自动关闭并开始同步。
3. 需要定时同步的话，在设置里勾选「自动同步」（自动同步时不会弹登录窗口，登录过期会在左下角提示）。

登录状态保存在本机的软件数据目录里（只在这台电脑上用）。平时微软账号会自动续期；彻底过期时点「同步 D365」会再弹一次登录窗口。

## 运行与打包

需要 Python 3.10 及以上，以及本机装有 Google Chrome 或 Microsoft Edge（Windows 自带 Edge）。

开发运行：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py          # 桌面窗口
.venv/bin/python main.py --web    # 网页模式 http://127.0.0.1:8765
```

打包（**必须在目标系统上打包**，Mac 打不出 exe）：

- Mac：`./build_mac.sh` → `dist/工程师排班管理.app`
- Windows：双击 `build_windows.bat` → `dist\工程师排班管理\工程师排班管理.exe`（整个文件夹一起复制给同事）

Windows 版的窗口用系统自带的 Edge 以「应用模式」打开（没有地址栏，关掉窗口即退出程序），不依赖 .NET；找不到 Edge 时才退回 pywebview。

### 在线更新

软件启动时会自动检查 GitHub Releases 有没有新版本（可在「设置」里关闭，也可以手动点「检查更新」）。有新版本时左上角出现绿色的「⬆ 新版本」按钮，点开能看到更新内容，「下载并更新」→「立即重启更新」后，软件会关闭、替换成新版本并自动重新打开。数据库和 D365 登录状态在系统的应用数据目录里，更新不受影响。

- 发布新版本：改好代码推送后，打一个更大的版本标签（如 `v1.1.0`）并推送，CI 会把标签号写进程序并发布安装包，客户端就能检测到。
- Windows 版如果放在 `C:\Program Files` 这类需要管理员权限的目录，自动替换会失败；请放在用户自己的目录（如桌面、文档）。
- Mac 版只支持 Apple 芯片；在线更新下载的新版本不会被系统标记为“来自网络”，所以不会再弹出“无法验证开发者”。
- v1.0.0 还没有在线更新功能，需要手动下载一次 v1.1.0 及以后的版本，之后就能在线更新了。

### GitHub 自动打包

仓库里的 `.github/workflows/build.yml` 会在每次推送到 `main` 时，在 GitHub 的 Windows 和 Mac 机器上各打一个包，并用网页模式启动一次做冒烟测试：

- 下载：仓库的 **Actions** 页 → 点最新一次「打包」→ 页面底部 Artifacts 里的 `EngineerScheduler-windows` / `EngineerScheduler-macos-arm64`（保留 30 天）。
- 发版：打一个 `v` 开头的标签并推送，两个包会自动发布到 **Releases**：

```bash
git tag v1.0.0
git push origin v1.0.0
```

Mac 包只支持 Apple 芯片（M 系列），而且没有苹果开发者签名：第一次打开如果提示“无法验证开发者”或“已损坏”，在终端执行 `xattr -dr com.apple.quarantine /Applications/工程师排班管理.app` 后再打开（路径换成实际位置）。Windows 首次运行可能出现 SmartScreen 提示，点「更多信息 → 仍要运行」。

## 数据存放位置

- Windows：`%APPDATA%\EngineerScheduler\`
- Mac：`~/Library/Application Support/EngineerScheduler/`

里面的 `data.db` 是全部数据（SQLite），`browser-profile/` 和 `d365-session.json` 是 D365 登录状态。换电脑时复制 `data.db` 即可，登录需要重新做一次。

## 代码结构

```
main.py               入口（桌面窗口 / --web 网页模式）
backend/db.py         SQLite 表结构、设置
backend/logic.py      排班/派单规则（对应原 Excel 公式和宏）
backend/browser.py    Playwright 驱动 Chrome/Edge，保持 D365 登录、调 Web API
backend/d365.py       mcs_serviceorder 查询与字段映射
backend/sync.py       同步流程（拉单 → 订单清单 → 派单/排班）
backend/parts.py      配件：借料归还状态、收费汇总
backend/workload.py   工作量：按时间段统计每位工程师的上门、工时、超期、配件和排班
backend/excel_io.py   Excel 导入导出
backend/updater.py    在线更新（检查 GitHub Releases、下载、替换并重启）
backend/version.py    版本号（发版时由 CI 按标签写入）
backend/api.py        界面调用的接口
ui/                   界面（HTML/CSS/JS，无外部依赖）
```

在设置里可以调整：D365 网址、订单来源、服务网点、回看天数、是否用 D365 状态覆盖本地状态、是否把预约写入派单、上午/下午分界、用哪个浏览器、同步时是否在后台运行浏览器。
